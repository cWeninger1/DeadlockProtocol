# Networking

The local Colyseus server listens on loopback port 2567 (override with PORT). GET /health reports readiness. The foundation room supports transport verification.

The foundry-movement room accepts two players. The server runs the shared movement and collision simulation at 60 Hz and broadcasts snapshots every third tick. Each client sends sequenced input with bounded axes and normalized yaw. The server queues at most 30 commands, consumes at most one per simulation tick and acknowledges the last command actually simulated. Elapsed wall time drives a fixed-step accumulator, with catch-up capped at 250 ms per callback. Position, health and other extra fields are rejected. Old sequences are ignored. Commands arriving together are retained in the bounded queue, including jump presses. A 180 messages-per-second connection limit also applies. When commands stop arriving, the server resumes idle physics after half a second to brake and finish airborne movement.

The browser predicts local movement at 60 Hz, replays unacknowledged input against authoritative snapshots, and eases small visual corrections. Local rendering interpolates between physics ticks. Remote bodies interpolate between snapshots in a 100 ms buffer. Player-to-player collision remains outstanding. Combat uses server-authoritative body hits and shared freight occlusion. The movement room exposes a connection status and a return-to-menu reconnect path. Automatic reconnection is outstanding. The local range retains the Phase 2 combat sandbox.

Run npm run dev, then open two browser tabs and select Join multiplayer range in both. Two players share a room. Additional players create another room. VITE_GAME_SERVER_URL selects the server endpoint, defaulting to http://127.0.0.1:2567. Local tests use ports 5174 and 2568. Cross-machine deployment, Firebase authentication and secure WebSocket hosting require later setup.

Combat intent adds bounded pitch, pressed/held trigger state, reload, selected weapon and life generation. The server validates these inputs, owns loadouts and health, and replicates team, score and weapon state with movement snapshots. Old-life commands are acknowledged but cannot move or fire after respawn. Reloads and equip timers continue on server time even when input pauses. Respawn is permitted only while dead and after a one-second delay. It keeps the same connection and team. Disconnecting leaves the room and discards that session's scores.

Shot tests use current server positions, with no historical rewind or lag compensation. Weapon visuals and ammunition wait for authoritative snapshots; responsiveness under internet latency remains future work. Teams contain one player each in this test room. The separate round mode adds Phase 4 rules; competitive spawn/layout balancing remains outstanding.

The foundry-rounds room shares movement/combat simulation but adds server-owned round state. Join round test selects this room; the multiplayer range still uses foundry-movement. Round commands must include the current epoch from the snapshot. Wrong or absent epochs cannot move or fire. Commands submitted during waiting, warmup, freeze or ending are acknowledged but inert. Each transition drains the queue, and spawn resets increment life IDs. Clients cannot request phase changes, supply scores or respawn during rounds.

Round snapshots publish phase, epoch, round number, end tick, result and team score. They use the same 60 Hz clock and 20 Hz snapshot cadence. When a team leaves, the room returns to waiting with zero team scores; a replacement starts warmup. Combat tests remain local and unauthenticated pending later identity/hosting work.

Objective interaction uses the same sequenced input stream and epoch/life checks. A consumed interact=true command maintains hold for up to 30 ticks without another accepted command; interact=false cancels immediately when consumed. Stationarity, grounding, alive status, team, carrier and range are checked on every simulation step. Snapshot round.objective contains carrier, site, planted position and action start tick; HUD progress derives from these server ticks. Planting changes the epoch and clears queued controls. The planted clock continues even after attacker death. Team disconnects still abort to waiting.

Match snapshots now carry Alpha/Bravo scores, swapped-side state, match winner/draw and the configured half/win format; player snapshots include stable squad identity. Halftime increments the epoch, clears queued/held input, swaps roles and resets lives. The next freeze assigns the objective to the new attacker. Clients cannot choose match rules or submit scores/results. Finished rooms reject gameplay through phase gates and lock matchmaking, while retaining the final state after departures. Mid-match departures still abort to waiting and restore initial squad roles.

Spectator mode is a client presentation of existing snapshots. Dead clients continue receiving authoritative player/objective updates and sending idle commands. Camera selection stays local, and the server's dead/phase gates still block gameplay. The current two-player test replicates the entire scene; team-only spectator replication for larger matches remains outstanding.

Round snapshots now include each member's economy and loadout ownership. The initial two-player test exposes balances in snapshots, though the HUD displays only your own; teammate-only financial visibility remains a later replication task. Clients send buy messages containing only action (buy/refund), rifle item, epoch and life. Additional fields, unknown items, stale generations and invalid eligibility are rejected. buyResult carries a confirmation or reason; replicated money/ownership remains authoritative. Repeated purchases cannot duplicate ownership and repeated refunds cannot create money. Existing room message-rate limits also cover purchases.
